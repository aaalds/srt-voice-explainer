# 视觉语言

默认方向是**编辑纪录片 + 科学可视化**，不是“AI 科技风”。画面应像技术期刊、公共电视纪录片、
研究机构编辑短片或优秀新闻图解：尊重材料、层级清楚、节奏克制、有作者判断，但不把界面感当成专业感。

判据不是“看起来够不够酷”，而是：观众能否立刻看见证据、关系和结论；删掉装饰以后信息是否更清楚；
这一帧是否像为当前主题专门设计，而不是换一组文字就能复用的模板。

## 默认视觉注册：editorial-documentary

- **证据先于界面。** 论文图、表格、数据、真实产品画面、实拍或代码证据是主体，不是卡片里的缩略图。
- **排版先于装饰。** 用字号、字重、留白、裁切、对齐和少量规则线建立层级；阴影、描边、圆角不是必需品。
- **材料决定视觉注册。** 在 `source-native / paper-diagram / footage-led / data-editorial` 中选择主方向，
  也可定义更贴题的方向，并在 `design.md` 解释理由。`editorial-documentary` 是判断原则，不是固定暖白模板。
- **材料决定色彩。** 暖白/纸色/炭黑/低饱和灰只是常用起点；从来源图中提取一个克制强调色，
  但“单一强调色”只约束自绘覆盖层，不强制改色论文原图、品牌色或真实影像。
  不默认“深黑 + 荧光绿/青/橙”。深色只在夜景、屏幕素材或题材确有理由时使用。
- **中文承担叙事。** 英文只保留官方术语、模型名和必要单位，不凭空创造 `SYSTEM / EVIDENCE / PIPELINE`
  一类装饰标签，不用全大写英文制造专业感。
- **画面有人的编辑判断。** 允许不对称、留白、跨页式裁切和安静停留；不把所有信息塞满，也不追求每秒都动。

证据充足的题材，设计前收集 6–12 张一手视觉材料并确定三张“锚点画面”；证据不足时收集全部
真正相关的材料，禁止为凑数量引入弱相关素材。没有合适一手图时，优先做清楚的二维解释图；
不得用与内容无关的 AI 图片补空位。

## 明确禁止当默认设计

- 蓝紫霓虹渐变、渐变文字、全屏线性渐变
- 默认深黑背景配荧光绿、荧光青或警示橙
- 玻璃拟态卡片、发光边框、悬浮圆角卡片阵列
- 无意义粒子、光球、科技 HUD、假 3D 全息界面
- 每屏同一个居中标题加三张卡片
- 每屏重复固定顶栏、章节进度、细线框架、右上角编号
- 用全大写英文 kicker、斜杠标题、伪参数标签填补空白
- 把每个名词都框起来，或把流程节点全部做成同尺寸圆角卡片
- 过量的 `01 / 02 / 03` 编号、十字准星、网格坐标和装饰性代码
- 过量辉光、镜头光晕、故障特效、模板化转场
- emoji 充当图标、随手画的品牌 Logo、与讲解无关的 AI 图片
- 大段字幕铺满画面、所有元素用同一种上浮淡入
- 仅为了"显得高级"而用铬金属、液态玻璃、高饱和赛博朋克

这些不是"品味问题"，它们的共同点是**不承载信息**：换掉讲解内容，这些元素一个字都不用改。

## 证据驱动的镜头语法

论文、模型和技术讲解优先按以下顺序组织，不必每次完整走一遍：

1. **建立出处**：先让观众看见原图、原表或真实场景，并标清 Figure / Table / 来源。
2. **局部裁切**：只放大当前句子涉及的结构，保留足够上下文，避免把整张论文图缩到不可读。
3. **关系标注**：用一条线、一个框、一次遮罩或颜色差说明因果、流向和对比。
4. **解释性重构**：原图确实无法读清时才重画，并标注“解释性重构”，不得伪装成论文原图。
5. **回到结论**：最后用一句短结论或一个真实数字收束，不再堆第二套卡片总结。

同一章节在以下画面类型中轮换：满版证据、局部特写、解释图、数据图、克制结论页。
不要让九章都使用“标题 + 左右两栏 + 底部大数字”的相同外壳。

## 色彩、字体与界面密度

- 色彩遵循约 70/20/10：大面积中性色、次级结构色、单一强调色。强调色面积过大就失去强调作用。
- 不使用纯黑 `#000` 配高饱和 RGB；深色画面优先炭黑、墨蓝灰或纸张反相色，保持真实材质。
- 标题采用自然中文短语，不写广告口号。章节标题只在建立章节时出现，不必常驻每个镜头。
- 正文优先正常句式与中英文混排，不把中文硬拆成英语式全大写模块。
- 圆角通常为 0–8 px；同屏有明确边框的容器原则上不超过 2 个。能用留白和规则线解决，就不做卡片。
- 阴影只用于表达前后层级；没有层级关系就不用。论文图不套发光框，不加“高科技”蒙版。
- 固定顶栏、进度和章节号跨两个及以上场景常驻，且没有用户明确要求或叙事功能 → FAIL。
  字幕、来源署名和必要导航可以例外，但须在审计中说明，且固定 UI 总面积不超过约 5%。

## 竖屏构图

**从第一行 HTML 就是 1080×1920。** 禁止做 16:9 再居中裁切、缩放或补背景。

- 每个场景必须有清晰主次与视觉路径。满版证据可单层呈现；第二层只用于出处、标注、比较或空间关系，
  禁止为了“有层次”强加背景纹理、外框、卡片或装饰图形。
- 竖屏优先：上下分区、中心轴、纵向流程、纵深推进、局部放大。
  避免照搬横屏的左右双栏、宽表格、一行排满多个卡片。
- 每屏一个主焦点 + 一个辅助信息层。复杂概念**按步骤逐层建立**，
  不要把完整大图一次缩小塞进竖屏。
- 用边缘锚定、纵向分区、比例差和结构线填满画面，不做松散网页布局。
- 矩阵、对比关系、多头结构这类横向内容：先展示局部，再通过缩放或折叠揭示整体。

## 字号与安全区（1080×1920）

| 项 | 值 |
| -- | -- |
| 标题 | 72–130 px |
| 正文 | 34–50 px |
| 小标签 | ≥ 24 px（原则上 24–30 px） |
| 普通内容边距 | 左右 ≥72–90 px，顶部 ≥120 px，底部 ≥180 px |
| 核心信息（标题/关键数字/公式/字幕）额外避开 | 顶部 140 px、底部 260 px、右侧 140 px |

顶/底/右的额外区域是平台界面覆盖区（点赞栏、账号信息、进度条）。
**装饰性元素可以延伸至出血区**，核心信息不行。
字幕放画面下部但高于底部安全区，且不得遮挡当前正在解释的核心图示。

平台简介、标题、标签和交互栏的实际高度会随账号与发布文案变化；不能把某次预览里“刚好没挡住”
当成永久安全。按配置中的保守覆盖区设计，并把核心信息尽量放在中央内容舞台。字幕轨道与平台覆盖区
是两层独立约束：字幕自身没有越界，也可能在画面内部盖住公式、代码或图示。布局时按全片最高字幕框
预留间距，不能只按一行字幕估算。

`safe_area_check.py` 会叠加蒙版统计越界像素。底部区里只剩装饰性元数据（章节序号之类）是可以的。
最终还要对公式/代码密集帧、字幕最高帧、转场帧和用户指定时间点做语义遮挡检查；均匀抽帧不能替代
精确时间点复核。

对比度按 WCAG AA 检查。失效态/次要文字最容易翻车——
`#4a423c` 在深墨底上只有 3.4:1，要提到 5:1 以上（见 pitfalls R4）。

## 公式与代码画面

- 公式先给一般形式，再把成立条件贴在化简式旁；禁止只展示特例、靠稍后的旁白补条件。
- 多行公式按等号、积分范围、条件或推导层级断行，不使用普通正文自动换行。
- 代码是证据：当前讲解行高亮，相关变量保持固定配色，未讲行降权；不使用纯装饰性代码雨。
- 代码过长时按算法步骤分段切换，不做持续自动滚屏；避免观众同时追滚动代码、字幕和旁白。
- 公式、当前代码行、关键结论与字幕至少保留一个正文字号的垂直间隔，并避开平台覆盖区。
- 公式/代码切换发生在旁白语义边界；转场不得盖住运算符、下标或当前高亮行。

详细的内容正确性和时间点审计见 `technical-explainer.md`。

## 论文图标注几何

框、线、箭头和局部放大不是装饰，它们必须与源图结构建立可复算的几何关系：

- 在源图坐标中记录模块 bbox 和端口点，再用同一套 crop/scale/offset 变换到画布坐标；禁止框、线、
  标签各自凭肉眼写一套常量。
- 框线与模块内容保持 8–16 px 余量；标签优先放在框外，不能用实心标签盖住论文文字。
- 连接使用单一连续 path，箭头只作为终点 marker。线段必须从上游端口实际连到下游边界，
  不得出现箭头上下各一截线、箭头悬空或某一路没有接入目标。
- 论文图发生缩放、位移或裁切动画时，覆盖层与图像必须共享变换容器，或由同一时间函数计算；
  不能让图动而框留在旧坐标。
- 讲到某模块才放大/高亮对应区域，入场时间绑定关键词发音窗口。需要从局部回到整体时，先撤标注
  再复位，避免同时出现两个互相冲突的框。
- 对每个框选、连接或遮挡修订抓取精确帧与前后邻帧；均匀 contact sheet 不能证明几何始终正确。

已有成片的局部图示修复流程见 `revision-repair.md`。

## 运动

- **每个动态对象都要有明确运动动词**：分裂、聚合、锁定、采样、折叠、写入、遗忘、
  缓存、旋转、填充、削平、拼接、重排、滑动、收缩。不是笼统的"淡入"。
- 重点动画直接表现知识关系：数量、方向、层级、因果、比较、状态变化、计算复杂度。
  n×n 矩阵要**真实增长**，采样点要**真实聚拢**，闸门要**真实开合**，缓存要**真实增长**——
  而不是让关键词动起来。
- 一个语义节拍通常只保留 1 个主动作；一个场景最多使用 2–3 种运动规则。没有关系要解释时，硬切、
  短叠化或静态停留优于持续漂浮。论文图允许稳定停留 4–9 秒，让观众真正阅读。
- 转场由语义驱动：概念延续用匹配运动或短交叠，章节切换用硬切或 0.2–0.5 s 的克制转场。
  不滥用炫技 shader。切点落在旁白静音区，不能截断词尾或盖住下句第一个关键词。
- 装饰必须与概念有关。只有分镜明确把背景定义为动态画面时，才允许缓慢、可控、
  **可寻址**且确定性的环境运动。静态背景不得漂移、呼吸缩放或逐帧刷新随机噪声。
- 每 2–6 秒的有意义变化应优先来自承载知识关系的前景对象。允许有设计意图的静态停留；
  禁止为了消除 `freezedetect` 报告而晃动文字或背景（见 pitfalls R5）。

避免“AI 动效节拍”：所有元素依次上浮、数字不断滚动、卡片逐张弹出、边框循环扫光、背景永远缓慢缩放。
它们给人“有动画”的错觉，却没有增加理解。需要节奏时，优先改变证据裁切、标注范围和比较对象。

## 静止元素稳定性

静止不是“几乎不动”，而是入场结束后在像素坐标和字形渲染上都锁定：

- 静止标题、正文、标签、公式和图标标记 `data-stability="static"`；动画对象标记
  `data-stability="dynamic"`。
- 静止文字不要放进持续执行 `translate`、`scale`、`rotate`、滤镜或透视动画的父容器。
  镜头需要移动时，文字放在独立的屏幕空间层。
- 字体在首帧前加载完成并内嵌；禁止 fallback → 正式字体的中途切换。字号、字距、行高、
  容器宽高和静止坐标优先使用整数像素，避免子像素取整造成边缘跳动。
- 静止背景不使用手持镜头抖动、缓慢推拉、呼吸缩放、随机 `background-position`、
  每帧随机噪声或不确定粒子。若素材本身是视频或动态仿真，必须标记为动态并说明原因。
- 入场动画结束后，以至少 5 fps 采样：静止元素 x/y/width/height 最大漂移均 ≤0.25 CSS px，
  transform 和字体相关 computed style 恒定；最终无损帧的静态背景全局对齐漂移 ≤0.5 输出像素。
- 自动检测到的 ≥4 s 静止段若是有意阅读停留，写入 `video_work/VISUAL_STABILITY_REPORT.json`：
  根对象含 `"status":"PASS"`，每段记录 `start`、`end`、非空 `reason` 和 `reviewed:true`。
  报告未覆盖的静止段仍为 FAIL；不能用一条全局说明批量豁免。
- 人眼逐帧或来回拖动检查时，只要能感到文字、边缘或背景在“摇”“呼吸”“漂”，就判 FAIL；
  数值门禁通过但肉眼仍晃，同样必须修。

## 全片一致 + 每章不同

同一套色板、字体、网格、运动语法贯穿全片；**同时每章要有不同的空间组织和运动逻辑**。
九章用同一个"标题+三卡片"模板，即使配色统一也是模板化。

每章先在 `chapters.json` 的 `world` 字段里写清这一章的空间组织是什么、
和上一章有什么不同，再开始写 HTML。

## 换题材就要重做视觉隐喻

**禁止机械复用上一支片子的图形。** 视觉隐喻是从这一份稿件的内容里提炼的；
换了字幕内容还沿用旧图形，画面就和讲解脱节了——那正是本节开头要避免的
"换掉内容也一个字不用改"的失败模式。

## 反 AI 风格门禁

最终 contact sheet 必须覆盖每个独立视觉场景的至少一张入场完成帧，每章至少 3 帧。
逐项回答并写入 `video_work/STYLE_AUDIT.md`；每项必须记录 `frame/scene`、出现次数或覆盖时长、
`PASS/FAIL` 与例外理由，不能只写主观总结：

1. 去掉文字后，是否有两个及以上场景使用相同卡片骨架或无叙事功能的固定界面外壳？是 → FAIL。
2. 是否出现来源中不存在的英文大写标签、伪参数、编号或“证据感”装饰？是 → 删除。
3. 是否默认使用黑底荧光色、渐变、辉光、玻璃或 HUD 来表示“技术”？是 → FAIL。
4. 是否有三张以上同尺寸卡片并列，但卡片之间没有真正比较关系？是 → 重构空间层级。
5. 一手图表是否可读，还是被缩成角落缩略图、外面再套一层 UI？后者 → FAIL。
6. 动画是否解释了数量、方向、因果、层级、比较或状态变化？不能明确回答 → 删除动画。
7. 标题是否像人写的章节标题，还是斜杠、全大写英文和口号的组合？后者 → 改写视觉标题。
8. 把成片缩到 25% 看 contact sheet，是否像同一套 AI 科技模板换了内容？是 → 重做视觉系统，
   不能只换颜色、字体或圆角。
9. 公式、代码、字幕和平台 UI 是否各有独立空间？用户指定时间点、字幕最高帧与转场帧是否逐帧复核？
   否 → 不得以均匀 contact sheet 或安全区像素统计代替。

审计是阻断式门禁。单帧偶发的小标签可以人工说明；相同模式跨两个场景重复，默认判为系统性模板问题。
