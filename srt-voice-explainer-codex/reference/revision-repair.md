# 已有成片的局部修订与验收

仅在用户要求修改既有成片、修音、重混、改局部框线或复核指定时间点时读取。
目标不是“重新做一遍”，而是让允许变化的区域可枚举、可复验，其他区域保持稳定。

## 1. 先定义补丁边界

开始前保存并记录上一版：成片、旁白母带、`alignment.json`、aligned SRT、micro-script、
发音台账、QA 报告与 SHA-256。建立补丁表，每项至少包含：

- 用户给出的时间点与对应 beat id；
- 允许改变的口播词、音频时间槽或画面元素；
- 必须保持不变的 canonical `text`、字幕、画面流、总时长或后续时间轴；
- 变更后的可观察验收条件。

时间点只是入口，beat id 才是稳定身份。音频重生成后时间可能漂移，不能继续拿旧秒数猜同一句。

## 2. 发音修复：连读不等于改音

对重复词、组合词和用户点名专名执行以下顺序：

1. 在 `PRONUNCIATION_LEDGER.json` 锁定独立词的音素、重音和 TTS 表示。
2. 组合词声明 `components`；每个组成词分别生成一个最小样片，再生成组合词样片。
3. 先 A/B 试听“独立词 vs 组合词中的同一组成词”，再检查组成词之间的停顿。
4. `pronunciation_probe.py` 只提供逐词时间戳和 ASR 候选。ASR 的整句相似度、正字法或近似拼写
   不能代替听感判断；`Ziva`、`Zeeva` 等转写差异需要结合音频判断。
5. 把全部出现位置、听感结论、ASR 证据、组成词一致性与 gap 写进
   `video_work/PRONUNCIATION_QA.json`。任何出现位置未检查，状态不得写 `PASS`。

推荐结构：

```json
{
  "status": "PASS",
  "method": "A/B listening plus local word timestamps",
  "checks": [
    {
      "term": "Zeva-Ego",
      "components": ["Zeva", "Ego"],
      "component_pronunciations_match": true,
      "continuity_required": true,
      "allowed_gap_ms": 80,
      "max_gap_ms": 0,
      "occurrences": [
        {"beat": "b008", "result": "PASS", "evidence": "standalone and compound Zeva heard the same; 0 ms gap"}
      ]
    }
  ]
}
```

## 3. 时间槽锁定修音

如果只改少量旁白且用户没有要求画面重排，优先保留上一版 `alignment.json`：

1. 找到原 beat 的 `[start, end]`，计算精确样本数 `round((end-start) * sample_rate)`。
2. 生成候选音频后先验收关键词读法；不要先对整句做 `atempo`，否则专名元音和辅音也会变化。
3. 时长需要压缩时，优先删减静音、压缩非关键词分句或重生成更自然的短候选；把已验收专名区间
   当作保护区。实在装不进原槽，就重排后续 alignment 与画面，不能牺牲读音。
4. 将合格单元预处理到与时间槽**样本数完全相同**，再运行：

```bash
python "$SKILL/scripts/run_project.py" patch_audio_slots.py \
  --base deliverables/final_narration_v03.wav \
  --patches video_work/audio_patch.json \
  --output video_work/narration/narration.wav
```

`patch_audio_slots.py` 直接替换样本，不做混音归一化，不改变总采样数，并报告补丁区外最大差值。
它会拒绝重叠时间槽、采样率/声道不一致、时长不精确或覆盖源文件。

不要用多个有限长度流直接 `amix` 后乘固定增益来替换片段：旧版 ffmpeg 会按仍存活的输入数归一化，
短补丁结束后归一化系数变化，导致补丁之后整条旁白逐段变响。若特殊场景必须 `amix`，每个补丁流
都要先 `apad,atrim` 到完整节目时长，并在未修改区做差分验证；样本级替换仍是首选。

## 4. BGM 与最终混音

- 旁白修复后重新跑 sidechain 和节目级线性增益；不要沿用旧分析值假设新混音仍达标。
- 先比较新旧 pre-mix 的综合响度、LRA、真峰值和未修改段电平；异常大变化通常说明混音图有问题，
  不是需要更强 loudnorm。
- 节目级只做一次线性增益和限峰。最终指标必须在 AAC 成片上测。
- 画面完全不变时，从上一版成片复制视频流并 `-c:v copy` 重挂新音轨；比较视频流或抽帧哈希，
  证明没有无关视觉变化。

## 5. 论文图框选、箭头和素材遮挡

不要直接在最终画布上猜框坐标。为每张源图记录：源尺寸、裁切矩形、`object-fit` 模式、缩放比例和
画布偏移，再把源图 bbox 统一变换到屏幕坐标。框、标签和连接线共用这套变换。

- 框线留 8–16 px 内外边距，不穿过模块文字；标签优先放在框外安全带。
- 箭头由一条连续 path 和一个终点 marker 构成；线段必须在箭头尾部，而不是在箭头上下各留一截。
- 多输入连接先对齐端口中心，再连接同一目标边；不要让某一路看似“没接上”。
- 讲到某模块时，放大/高亮必须在关键词发音窗口内发生；不要提前常亮整张框图。
- 横屏素材放进竖屏时优先完整展示、智能裁切或上下分区；不得压扁，也不得让素材覆盖字幕/正文。
- 对每个用户点名时间抓取 `t-0.5s / t / t+0.5s`，同时检查框与模块的几何对应、字幕遮挡和动画状态。

## 6. 封面与发布文案（仅在用户要求时）

- 横屏 1920×1080、竖屏 1080×1920 分别重新构图，不能机械裁切同一张图。
- 标题先满足用户给出的字数档；正文只保留一个清晰冲突或收益，不堆模型名与宣传口号。
- 封面和简介沿用成片的事实边界；厂商自称、论文证据和编辑评价要分开写。
- 交付前验证尺寸、字体、Logo/论文图来源、标题字符数和移动端缩略图可读性。

## 7. 补丁交付门禁

局部修订至少要同时通过：

- canonical SRT 逐字一致，或有版本化脚本变更记录；
- `PRONUNCIATION_QA.json` PASS；
- 每个补丁单元时长/样本数与目标槽一致，或 alignment 已完整重建；
- 补丁区外音频增益无漂移，未授权画面帧无变化；
- 成片响度、真峰值、逐单元离散、同步、黑帧、静止段、指定时间点全部复验；
- 新版本号交付，旧成片不覆盖；候选与交付文件 SHA-256 一致。

任何一项没有证据，都只能写“待验收”，不能写“已完成”。
