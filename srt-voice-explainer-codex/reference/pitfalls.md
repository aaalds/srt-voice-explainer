# 历史缺陷清单

这条管线上真实发生过的缺陷，按发现顺序编号。每条记症状、证据、根因、修法、复验。
新项目开工前扫一遍——大部分坑不会因为换了题材就消失。

## R1 · 子 composition 的 JSON 数据块被运行时剥离

**症状**：9 条时间线全部未构建，画面停在静态第一帧。
**证据**：`check → console_error: Cannot read properties of null`。
**根因**：把节拍表放在 `<script type="application/json">` 里，HyperFrames 运行时会剥离它。
**修法**：节拍表改挂到 composition 内一个零尺寸子元素的 `data-beats` 属性上。
**复验**：runtime 0 error；快照确认动画生效。

## R2 · TTS 拖音

**症状**：`b002` 13.66 s / 19 字 = 1.39 字/秒（全片中位数 4.23）。
**证据**：草稿渲染 `freezedetect` 报该章有 8.1 s 静止——**画面的冻结检测抓到了音频的问题**。
**根因**：TTS 偶发的异常拖长，采样温度下的低概率分支。
**修法**：加时长上界拒绝（`0.55×字数 + 1.2s`）+ 受控换种子重生成（seed-offset 3）→ 4.88 s。
**复验**：3.9 字/秒；ASR 逐字正确。

> 换种子必须是**受控**的：基础 seed 固定、只对失败段用确定的 offset 重试，
> 这样整支片子仍然可复现。随机重试等于放弃复现性。

## R3 · 竖屏小字

**症状**：全片存在 18–23 px 标签，1080 宽竖屏上不可读。
**证据**：成片抽帧（ch6 逐维闸门的「留/扔」标签 18 px）。
**修法**：所有 <24 px 字号统一提到 24 px。
**复验**：`check` 0 error，重渲染后复核。

## R4 · 失效态文字对比度不足

**症状**：`#4a423c` 文字对比度 3.4:1，不满足 WCAG AA。
**证据**：`check → contrast_aa_failure #ch3-globalval`。
**修法**：失效态文字改 `#8d8275`（5.2:1）；`#4a423c` 只留给非文字元素。
**复验**：contrast 0 failure。

## R5 · 长时间完全静止

**症状**：24 段 ≥4 s 的"完全无可见变化"窗口。
**证据**：草稿渲染 `freezedetect`。
**旧修法的问题**：给纸张颗粒或整个背景持续漂移虽然能消除 freeze 报告，却可能让本应静止的
文字和背景产生“摇晃”“呼吸”感，尤其是动画挂在共同父容器或落在子像素坐标时。
**修法**：先判断该窗口是否为有意的静态停留；若不是，让流程线、数据点、遮罩、进度或其他
承载语义的前景对象发生确定性变化。静止文字与静止背景放在独立、无 transform 的像素锁定层。
若本来就是有意停留，在分镜和 QA 报告中标注，不为消除告警强行动背景。
**复验**：非刻意冻结窗口消失；有意静态窗口有记录；静止元素 bbox 漂移 ≤0.25 CSS px，
静态背景全局对齐漂移 ≤0.5 输出像素，逐帧肉眼无晃动。

> 动态元素必须确定性（seed 固定 / 纯函数 of time）；确定性只能保证复现，不能替代稳定性检查。

## R6 · 渲染器给音轨附加增益

**症状**：母带是 −17 LUFS，成片实测 −13.9 LUFS。
**证据**：`qa_video.py` 响度门禁 FAIL。
**修法**：用 −17 LUFS 母带 wav 重挂音轨（`-c:v copy`，画面零改动）。
**复验**：−17.00 LUFS / −1.20 dBFS。

> 教训：**所有音频指标都要在成片上测**，中间文件达标不算数。

## R7 · 母带头部残留换气引子

**症状**：`b056` 的关键词比发音早 470 ms 出现。
**证据**：`qa_video.py` 同步门禁 FAIL（350 ms）。
**根因**：母带头部残留 340 ms 换气声，`alignment.json` 的 start 是片段起点而非发音起点。
**修法**：拼装阶段把引子从头部移到尾部——**片段总长不变**，时间轴与画面不受影响。
**复验**：最大偏差 60 ms。

## R8 · 未挂载的 GSAP target

**症状**：一处环境光带只留下 CSS 与时间线，DOM 缺失。
**证据**：`check → GSAP target #sweep-band not found`。
**修法**：删除死代码；环境运动由 R5 的颗粒漂移承担。
**复验**：runtime 0 warning。

## R9 · 全片响度忽大忽小（交付后由用户指出）

**症状**：15 个旁白单元被错误衰减最多 46 dB，`b052` 峰值仅 0.005，实际近乎听不见。
**证据**：v01 成片实测逐单元响度 σ=8.57 LU、极差 47.06 LU、逐章偏差最大 6.55 LU。
**根因**：单元母带用了 ffmpeg `loudnorm`。该滤镜需要 ≥3 s 输入，短于 3 s 时测量值无效且不报错。
86 段里 15 段短于 3 s，**全部 15 段被毁，71 段 ≥3 s 全部正常**，相关性 100%。
**为什么没被原有门禁抓到**：
- 只测了整片综合响度——一个门控平均值，把 15 段的损伤稀释掉了；
- `silencedetect` 阈值 −50 dB 没触发，因为偶尔仍有采样越过阈值。

**修法**：单元级测量/归一化改为本地 BS.1770-4 门控实现（`scripts/loudness.py`，任意长度成立）：
线性增益到 −17 LUFS + 前瞻真峰值限峰，不做压缩；母带改存 float32（单元增益最高 +12 dB）；
落成 7 项自动门禁。只重跑音频母带并 `-c:v copy` 重挂音轨——**画面未重渲染**
（帧数据逐字节未变；`alignment.json` 逐字段比对无差异）。
**复验**：逐单元 σ **0.03 LU**、极差 **0.18 LU**、短时 σ **1.05 LU**、逐章偏差 **0.20 LU**；
同一批门禁跑在 v01 上 **6/6 FAIL**。

## R10 · Codex 沙箱中 TTS 导入高 CPU 假死

**症状**：日志停在 `generating N/N units` 和 Qwen 导入警告，长时间没有任何 raw wav；
Python 持续占用一个 CPU 核，终端结束后进程仍存活。
**证据**：堆栈停在 Numba `ensure_cache_path → tempfile._mkstemp_inner`；默认环境下
`import qwen_tts` 超过 45 秒不返回，把 `NUMBA_CACHE_DIR` 指到可写目录后约 6 秒完成。
**根因**：venv 位于 Codex 沙箱只读路径，Numba 优先尝试写包内 `__pycache__`；Windows
`tempfile` 在 ACL 判断与沙箱实际写权限不一致时重复尝试最多 10,000 次。
**修法**：所有脚本经 `run_project.py` 启动；在导入 qwen_tts 前把 Numba 缓存固定到
`video_work/.cache/numba`，启用严格离线模式，并加入单实例锁、状态文件、心跳和硬超时。
**复验**：运行时探针 PASS；导入在时限内完成；`tts_state.json` 和日志持续更新；人为把缓存
指向只读目录时仍回退到项目缓存；同一项目启动第二份 TTS 时立即拒绝。

## R11 · 均匀抽帧漏掉指定时间点的字幕遮挡

**症状**：contact sheet 整体正常，但用户在约 3:30 仍看到文字被画面遮挡。
**根因**：均匀抽帧没有命中短暂重叠区；安全区检查只看平台边缘，没有检查字幕与画面内部核心图示。
**修法**：新增 `TIMESTAMP_AUDIT.md`，覆盖用户点名的精确时间、前后 0.5 s / 2 s、字幕最高帧、
公式/代码密集帧和转场邻帧；逐帧记录字幕、核心元素 bbox 与人工语义判定。
**复验**：指定时间点及邻帧无重叠；核心信息不进入顶/底/右平台覆盖区。

## R12 · 把带条件的化简式写成一般公式

**症状**：终点更新只显示 `x_t + (1-t)v`，容易让观众误以为任意速度场都能一次直达终点。
**根因**：为了缩短画面，省略了积分和“区间内速度近似恒定”的成立条件。
**修法**：按“一般积分式 → 数值积分 → 常速度特例”分层展示，条件紧贴特例，不延后补充。
**复验**：公式、旁白、动画和推理代码四处使用同一方向；专项审计能明确指出一般式与特例。

## R13 · 数学标识符被 TTS 按排版符号猜读

**症状**：用户希望 `x_t` 读作“xt”，成片却读成“x 下标 t”。
**根因**：把展示用 LaTeX/下划线直接送入 TTS，没有为标识符维护独立朗读形式。
**修法**：在发音台账中分开 `text`、`screen` 和 `tts`；按用户偏好锁定读法，只重生成受影响单元。
**复验**：串联试听该标识符的全部出现位置；ASR 仅作辅助，人工确认全片一致。

## R14 · 代码口播与实际代码不一致

**症状**：口播声称“六行”，画面实际是七行，或把速度更新说成“减去噪声”。
**根因**：脚本按早期伪代码撰写，后来修改了实际代码却没有回查行数、变量语义和更新方向。
**修法**：屏幕只引用已保存、可运行的代码版本；生成口播前机械统计展示行，运行最小形状/输出测试，
并把公式到代码变量的映射写进 `TECHNICAL_EXPLAINER_AUDIT.md`。
**复验**：代码测试通过；口播中的行数、输入输出、更新方向与展示代码逐项一致。

## R15 · 为了连读而改坏组合词中的专名

**症状**：独立出现的模型名读法正确，进入“模型名-后缀”组合词后却换成另一套近似音；两词虽然
连得紧，但同一个专名前后听起来不是一个词。
**根因**：把“连读”错误理解成重写整个组合词，只验收了词间有没有停顿，没有核对组成词本身。
**修法**：在发音台账中给组合词声明 `components`；先做“独立词 + 组合词”最小样片，A/B 试听
每个组成词。连续性只通过缩短边界静音解决，不改变音素或重音。
**复验**：所有出现位置逐词回读/试听一致；需要连续衔接时，逐词时间戳 gap 不超过台账阈值；
结论写入 `PRONUNCIATION_QA.json`。

## R16 · 全句 ASR 通过，却漏掉专名的细微错音

**症状**：整句字符相似度合格，ASR 也给出看似接近的拼写，但用户仍能听出专名元音、重音或
组合词前缀不一致。
**根因**：把全文平均分和整句转写当成发音门禁；ASR 会把相邻近似音折叠成同一词，也会受语速、
中英混读和上下文影响。
**修法**：高风险词逐项提取全部出现位置；结合本地逐词时间戳、独立词/组合词 A/B 试听和官方或
用户指定读法验收。ASR 只提供证据，不自动判 PASS。
**复验**：`PRONUNCIATION_QA.json` 对每个 occurrence 都有非空证据和人工结论。

## R17 · 局部修音后，补丁之外的旁白逐段变响

**症状**：只替换三个短音频槽，后半片的旁白和 BGM 比上一版明显更响；综合响度/LRA 大幅变化。
**根因**：用旧版 ffmpeg `amix` 混入有限长度的延迟补丁，再乘固定增益。补丁流结束后，`amix`
按存活输入数改变归一化系数，导致原旁白增益随时间漂移。
**修法**：优先使用 `patch_audio_slots.py` 做样本级槽位替换。必须 `amix` 时，把每个补丁流
`apad,atrim` 到完整节目时长，并对补丁区外做差分和响度对比。
**复验**：总采样数不变；补丁区外最大差值为 0 或在已声明编码误差内；pre-mix 指标与上一版相符。

## R18 · 论文框线、箭头和素材位置靠肉眼猜

**症状**：框没有覆盖讲解模块，箭头与连线断开或上下错位，横屏素材压窄/遮住文字；静态截图看似
接近，动画过程中却漂离目标。
**根因**：源图裁切、`object-fit`、缩放和画布偏移各自计算；框、标签和箭头没有共享同一坐标变换，
且只看均匀 contact sheet，没有复核用户点名帧。
**修法**：在源图坐标中定义 bbox/端口，统一变换到屏幕坐标；箭头用单一 path + 终点 marker；
对点名时间抓 `t-0.5/t/t+0.5` 三帧检查几何对应与遮挡。
**复验**：框线不遮模块文字、所有连接端点相交、素材保持纵横比、字幕与正文无遮挡。

## 从历史缺陷里能带走的八条

1. **一个通过的聚合指标可以掩盖严重的局部缺陷。** 测分布，不只测均值（R9、R6）。
2. **门禁必须被证明能失效。** 拿修复前的产物跑一遍，跑不出 FAIL 就是门禁写错了（R9）。
3. **一个子系统的检测器会抓到另一个子系统的 bug。** 画面的 `freezedetect` 抓到了 TTS 拖音（R2）。
   不要因为"这是画面检查"就忽略它对音频的指向。
4. **路径存在不等于运行时健康。** 沙箱里的真实写权限必须通过一次限时导入探针验证（R10）。
5. **均匀抽帧不能证明某个时间点没有问题。** 用户点名时间和高风险帧要精确复核（R11）。
6. **技术讲解要维护一套语义真相。** 一般式、特例、读法、代码和动画必须互相可核对（R12–R14）。
7. **连续性和同音是两条独立约束。** gap 为 0 不能证明组成词读法一致（R15–R16）。
8. **局部修订先证明补丁隔离。** 时间槽外的音频、画面和时间轴不应因修一个词而变化（R17–R18）。
