# 历史缺陷清单

这条管线上真实发生过的缺陷，按发现顺序编号。每条记症状、证据、根因、修法、复验。
新项目开工前扫一遍——大部分坑不会因为换了题材就消失。

## R1 · 子 composition 的 JSON 数据块被运行时剥离

**症状**：9 条时间线全部未构建，画面停在静态第一帧。
**证据**：`check → console_error: Cannot read properties of null`。
**根因**：把节拍表放在 `<script type="application/json">` 里，HyperFrames 运行时会剥离它。
**修法**：节拍表改挂到 composition 内一个零尺寸子元素的 `data-beats` 属性上。
**复验**：runtime 0 error；快照确认动画生效。

## R2 · TTS 拖音

**症状**：`b002` 13.66 s / 19 字 = 1.39 字/秒（全片中位数 4.23）。
**证据**：草稿渲染 `freezedetect` 报该章有 8.1 s 静止——**画面的冻结检测抓到了音频的问题**。
**根因**：TTS 偶发的异常拖长，采样温度下的低概率分支。
**修法**：加时长上界拒绝（`0.55×字数 + 1.2s`）+ 受控换种子重生成（seed-offset 3）→ 4.88 s。
**复验**：3.9 字/秒；ASR 逐字正确。

> 换种子必须是**受控**的：基础 seed 固定、只对失败段用确定的 offset 重试，
> 这样整支片子仍然可复现。随机重试等于放弃复现性。

## R3 · 竖屏小字

**症状**：全片存在 18–23 px 标签，1080 宽竖屏上不可读。
**证据**：成片抽帧（ch6 逐维闸门的「留/扔」标签 18 px）。
**修法**：所有 <24 px 字号统一提到 24 px。
**复验**：`check` 0 error，重渲染后复核。

## R4 · 失效态文字对比度不足

**症状**：`#4a423c` 文字对比度 3.4:1，不满足 WCAG AA。
**证据**：`check → contrast_aa_failure #ch3-globalval`。
**修法**：失效态文字改 `#8d8275`（5.2:1）；`#4a423c` 只留给非文字元素。
**复验**：contrast 0 failure。

## R5 · 长时间完全静止

**症状**：24 段 ≥4 s 的"完全无可见变化"窗口。
**证据**：草稿渲染 `freezedetect`。
**旧修法的问题**：给纸张颗粒或整个背景持续漂移虽然能消除 freeze 报告，却可能让本应静止的
文字和背景产生“摇晃”“呼吸”感，尤其是动画挂在共同父容器或落在子像素坐标时。
**修法**：先判断该窗口是否为有意的静态停留；若不是，让流程线、数据点、遮罩、进度或其他
承载语义的前景对象发生确定性变化。静止文字与静止背景放在独立、无 transform 的像素锁定层。
若本来就是有意停留，在分镜和 QA 报告中标注，不为消除告警强行动背景。
**复验**：非刻意冻结窗口消失；有意静态窗口有记录；静止元素 bbox 漂移 ≤0.25 CSS px，
静态背景全局对齐漂移 ≤0.5 输出像素，逐帧肉眼无晃动。

> 动态元素必须确定性（seed 固定 / 纯函数 of time）；确定性只能保证复现，不能替代稳定性检查。

## R6 · 渲染器给音轨附加增益

**症状**：母带是 −17 LUFS，成片实测 −13.9 LUFS。
**证据**：`qa_video.py` 响度门禁 FAIL。
**修法**：用 −17 LUFS 母带 wav 重挂音轨（`-c:v copy`，画面零改动）。
**复验**：−17.00 LUFS / −1.20 dBFS。

> 教训：**所有音频指标都要在成片上测**，中间文件达标不算数。

## R7 · 母带头部残留换气引子

**症状**：`b056` 的关键词比发音早 470 ms 出现。
**证据**：`qa_video.py` 同步门禁 FAIL（350 ms）。
**根因**：母带头部残留 340 ms 换气声，`alignment.json` 的 start 是片段起点而非发音起点。
**修法**：拼装阶段把引子从头部移到尾部——**片段总长不变**，时间轴与画面不受影响。
**复验**：最大偏差 60 ms。

## R8 · 未挂载的 GSAP target

**症状**：一处环境光带只留下 CSS 与时间线，DOM 缺失。
**证据**：`check → GSAP target #sweep-band not found`。
**修法**：删除死代码；环境运动由 R5 的颗粒漂移承担。
**复验**：runtime 0 warning。

## R9 · 全片响度忽大忽小（交付后由用户指出）

**症状**：15 个旁白单元被错误衰减最多 46 dB，`b052` 峰值仅 0.005，实际近乎听不见。
**证据**：v01 成片实测逐单元响度 σ=8.57 LU、极差 47.06 LU、逐章偏差最大 6.55 LU。
**根因**：单元母带用了 ffmpeg `loudnorm`。该滤镜需要 ≥3 s 输入，短于 3 s 时测量值无效且不报错。
86 段里 15 段短于 3 s，**全部 15 段被毁，71 段 ≥3 s 全部正常**，相关性 100%。
**为什么没被原有门禁抓到**：
- 只测了整片综合响度——一个门控平均值，把 15 段的损伤稀释掉了；
- `silencedetect` 阈值 −50 dB 没触发，因为偶尔仍有采样越过阈值。

**修法**：单元级测量/归一化改为本地 BS.1770-4 门控实现（`scripts/loudness.py`，任意长度成立）：
线性增益到 −17 LUFS + 前瞻真峰值限峰，不做压缩；母带改存 float32（单元增益最高 +12 dB）；
落成 7 项自动门禁。只重跑音频母带并 `-c:v copy` 重挂音轨——**画面未重渲染**
（帧数据逐字节未变；`alignment.json` 逐字段比对无差异）。
**复验**：逐单元 σ **0.03 LU**、极差 **0.18 LU**、短时 σ **1.05 LU**、逐章偏差 **0.20 LU**；
同一批门禁跑在 v01 上 **6/6 FAIL**。

## R10 · 0 宽元素上的 `scaleX` 什么都不画

**症状**：一组"单价"刻度条完全不显示，时间线、CSS、DOM 全都在。
**证据**：成片抽帧目检；`check` 0 error——**自动门禁抓不到，只有眼睛能抓到**。
**根因**：`.price-fill` 是 `position:absolute` 且只写了 `left/top/height`，没有 `width`。
宽度为 0 的元素做 `scaleX(0 → 1)`，缩放的是 0，渲染结果仍是 0。
**修法**：给它显式 `width: 150px`。
**复验**：三档刻度条正常长出。

> 推广：**任何要做 transform 的元素都必须是块级且有确定尺寸。**
> `scaleX` / `scaleY` 缩放的是既有几何，不是凭空造几何。行内元素同理
> （`<span>` 上的 transform 静默不生效，要 `display: block`）。

## R11 · 媒体面板伸进平台覆盖区

**症状**：实拍面板右边缘落在 x=1020，进了竖屏右侧 140 px 的点赞栏区。
**证据**：`safe_area_check.py`：ch5 单帧越界像素 20935 / 39478。
**根因**：先按"好看"定了 960 px 宽的取景框，再去对安全区。
媒体面板天生要宽，是最容易撞覆盖区的元素。
**修法**：取景框收窄到 880 px（60…940），各素材的基准取景参数按新宽度重算。
**复验**：越界像素降到 253 / 1125，且只剩装饰性琥珀边框。

> **先按安全区算可用宽度，再定构图**：`可用宽度 = 1080 − 左边距 − 右侧 140`。
> 反过来做一定返工，而且返工要重算所有取景参数。

## R12 · TTS 的稳定误读，换种子救不回来

**症状**：「之后 Sol 只做拆任务和**审代码**」里的「审」被稳定读成 `shěng`。
**证据**：逐段 ASR 六次回读全是「省代码」；而同一个词在另一段（b007）读法正确。
**尝试过但无效**：4 个受控种子、加换气逗号切断连读、同音字替换（婶/沈）。
**修法**：把这一句改写成语义等价、发音无歧义的「代码审查」，记进 `SCRIPT_CHANGES.md`。
**复验**：ASR 回读「代码审查」。

> 两条边界：
> 1. **换种子先试，但不要无限试。** 2–3 个受控 offset 之后仍不对，就是这个字符串
>    在这个上下文里的稳定行为，再试也是碰运气。
> 2. **只能改写自己写的稿子。** 用户口述的句子不许为了发音方便改掉；
>    那种情况要么调 `tts` 拼写，要么把问题连同两三个可选方案交回用户定。

## R13 · 整段 ASR 的词边界合并，制造假的发音缺陷

**症状**：`b012` 整段回读为 `lunaworker.toml代理`，看起来漏读了「子」。
**证据**：单独截取该段尾部 1.6 s 重新转写 → 「ML子代理」，字确实读出来了。
**根因**：whisper 把相邻的「L 子」合并进了 `.toml` 这个词形。
**修法**：宣布发音缺陷之前，先把可疑位置**单独截出来重转一次**。
**复验**：非缺陷，不重生成。

> 反过来也成立：整段 ASR **对上了**也不等于读对了（同音字）。
> ASR 是定位工具，不是判据；判据是人耳 + 写回台账的 `asr_variants`。

## R14 · 稳定性门禁在片头的假阳性

**症状**：`check_static_stability.py` 在 0.2–0.8 s 报全局漂移。
**证据**：那段时间标题、进度轨、色条、字幕同时入场，变化框自然铺满全屏。
**根因**：判据只看"变化像素少 + 变化框大"，没有看**持续多久**。
**修法**：加最短连续段 `MIN_RUN = 6`（≥1.2 s）。真正的摇/呼吸/漂会贯穿整个静止窗口，
入场只有几帧。
**复验**：正片 0 段漂移；加了 1 px 往复位移的坏样例仍判 17 段 FAIL——**门禁没被调成恒真**。

> 放宽阈值之后必须重跑坏样例。不重跑，就分不清"修好了"和"门禁瞎了"。

## R15 · 快照工具不解码视频

**症状**：`check --samples` 的快照里，实拍面板是一整块黑。
**证据**：同一时间点从草稿渲染里抽帧 → 画面正常。
**根因**：快照走的是无媒体解码的路径，`<video>` 在那里本来就不出画。
**修法**：不修。用草稿渲染抽帧确认媒体位置。
**复验**：t=55 s 的渲染帧内容正确。

> 别去"修"一个只存在于检查工具里的问题。先确认症状在**成片**上成立。

## R16 · 生成脚本覆盖手写文档

**症状**：`build_docs.py` 把手写的 `SCRIPT_CHANGES.md`（压稿逐条记录）整份覆盖成模板。
**证据**：文件从 7 KB 变成 1.5 KB，第 1 节写着"无删改"——而这一版恰恰删改过。
**根因**：生成器无条件写目标路径；同时它硬编码了 `TIMING_MODE = QUALITY_FIRST` 的措辞。
**修法**：生成的文件带 `<!-- generated-by: build_docs.py -->` 标记；
目标文件存在且**没有**这个标记时，生成版改写到 `SCRIPT_CHANGES.generated.md`，手写版不动。
措辞按 `CFG.timing_mode` 分支。
**复验**：手写文件字节数与 mtime 不变，生成版另存。

> 更普遍的教训：**文档生成器输出的断言必须由配置驱动，不能写死。**
> 一份自动生成的、内容为假的"合规声明"比没有更危险。

## 从 R1–R16 里能带走的六条

1. **一个通过的聚合指标可以掩盖严重的局部缺陷。** 测分布，不只测均值（R9、R6）。
2. **门禁必须被证明能失效。** 拿修复前的产物跑一遍，跑不出 FAIL 就是门禁写错了（R9）。
   放宽阈值之后要**重跑**坏样例，否则分不清修好了还是门禁瞎了（R14）。
3. **一个子系统的检测器会抓到另一个子系统的 bug。** 画面的 `freezedetect` 抓到了 TTS 拖音（R2）。
   不要因为"这是画面检查"就忽略它对音频的指向。
4. **自动门禁全绿不等于画面对。** R10 的刻度条彻底不显示，`check` 一个 error 都没有——
   逐格目检不是走过场，它是唯一能抓到"元素在但看不见"的手段。
5. **先确认症状在成片上成立，再动手修。** 检查工具自身的局限（R15）、
   ASR 的词边界合并（R13）都会伪造出不存在的缺陷；修一个假问题会引入真问题。
6. **生成器不许覆盖人写的东西，断言不许写死。** R16 里被覆盖的正是当次最有价值的文档，
   而覆盖上去的内容还是假的。
